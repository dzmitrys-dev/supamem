# Phase 08.1 Plan 02: Pure-Function Patcher Kernel Summary

ruamel.yaml-based pure kernel — detect / patch / hash three styles of Claude Code agent frontmatter (CSV, block-list, flow-style/malformed/no-frontmatter skips) with zero filesystem I/O and end-to-end idempotency.

## What Shipped

### Task 1 — detect_tools_state + frontmatter_block + block_sha256 (commit `de96412`)

- **`frontmatter_block(text)`** — extracts the leading `---\n…\n---\n` block via regex anchored at `\A` with a 200-line scan guard (P8). Returns `None` if delimiters are missing or not at file start.
- **`block_sha256(text)`** — SHA-256 hex digest of the frontmatter block bytes with `\r\n → \n` normalization (D-UNDO-03 / Q4). Empty-bytes hash on missing frontmatter (deterministic; never raises).
- **`detect_tools_state(text)`** — classifies into seven states (`covered`, `inheritance`, `patchable_csv`, `patchable_list`, `skipped:flow`, `skipped:malformed`, `skipped:no-frontmatter`). Strips markdown `---` fences before handing inner YAML body to `ruamel.yaml.YAML(typ='rt')`. Catches only `YAMLError` — unrelated exceptions propagate (D-FAIL-01 swallow happens at the I/O wrapper layer in Plan 03, not in the pure kernel).
- **`_is_covered(tokens)`** — D-COVER-01 lenient match for `mcp__*`, `mcp__supamem__*`, or `mcp__supamem__<literal>`. Rejects Q2 non-canonical forms: bare `mcp__supamem` (no `__*` suffix) and any token containing `*.` (single-dot server pattern).
- **11 RED stubs flipped GREEN** across detect-state and block_sha256 tests (12 including Wave 0 smoke).

### Task 2 — patch_yaml with style preservation + idempotency (commit `39184df`)

- **`patch_yaml(text)`** — returns `(new_text, ManifestFragment | None)`. No-op `(text, None)` for non-patchable states.
- **CSV branch** — textual tokenize/append/rejoin preserves the user's original spacing (P3): joiner is `", "` only when at least one token had a leading space pre-strip, else `","`. Inline `# comments` on the tools line survive by splitting them off before tokenization and re-appending.
- **Block-list branch** — ruamel round-trip with `_yaml.indent(mapping=2, sequence=4, offset=2)` reproduces the 2-space sibling indent (`  - item`) that Claude Code agents conventionally use. Comments inside the frontmatter (e.g. `with-comments.md`'s standalone comment line) round-trip verbatim per Wave 0 verification.
- **`ManifestFragment` TypedDict** populated with `original_frontmatter`, `original_frontmatter_sha256`, `patched_frontmatter_sha256`, `tools_form` ∈ {`"csv"`, `"block-list"`} for Plan 03's manifest writer.
- **Idempotency proven end-to-end** — calling `patch_yaml` on already-covered text returns `(text, None)`; calling `patch_yaml` twice on patchable input — first call patches, second call detects coverage and returns `(unchanged, None)`. Test 14 enforces both directions.
- **5 RED stubs flipped GREEN** (CSV space/no-space, block-list indent, comment preservation, idempotency).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] Markdown `---` fences fed to ruamel.yaml triggered "expected single document" error**

- **Found during:** Task 1 verify (initial run failed 7/12 detect-state tests with `skipped:malformed`)
- **Issue:** `frontmatter_block` returns the block including its `---\n` delimiters. Passing that string to `ruamel.yaml.load` makes ruamel see two YAML doc separators and raise `YAMLError("expected a single document in the stream … but found another document")`. The plan's pseudo-code passed the block directly to the parser; this slipped past the planner because the Wave 0 smoke fed only the inner body.
- **Fix:** Added explicit fence-stripping (lines that match `---\n` prefix and `\n---\n` / `---\n` suffix) before `_yaml.load()` in both `detect_tools_state` and `_patch_block_list`. P2 in RESEARCH.md flags this exact pitfall ("frontmatter `---` is a markdown convention, not a YAML doc separator") so the fix aligns with prior research.
- **Files modified:** `src/supamem/install/agent_patcher.py`
- **Commit:** `de96412` (rolled into Task 1 commit — discovered before commit boundary)

**2. [Rule 1 — Bug] ruamel default block-sequence indent flushes left, violating D-YAML-03**

- **Found during:** Task 2 verify (`test_patch_block_list_appends_with_matching_indent` failed)
- **Issue:** Default ruamel emit produces `tools:\n- Read\n- Bash\n…`, but the fixture (and Claude Code convention) uses `tools:\n  - Read\n  - Bash\n…`. Re-emitting flush-left would technically be valid YAML but visually reformats the user's file — D-YAML-03 forbids reformatting.
- **Fix:** Configure module-level `_yaml.indent(mapping=2, sequence=4, offset=2)`. The `offset=2` is the key parameter — it shifts the `-` two columns right of the parent key, reproducing the `  - item` style.
- **Files modified:** `src/supamem/install/agent_patcher.py`
- **Commit:** `39184df` (rolled into Task 2 commit)
